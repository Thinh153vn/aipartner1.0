# GROWTH PARTNER

日本のSIerで働く **BrSE（ブリッジSE）** および新人SE向けの、自律型AIアシスタントです。

日々のタスク・カレンダー・学習目標（MBO）を一つの画面で把握し、遅延の検知、日報作成、オフショア成果物のレビューをAIが支援します。画面上の文言はすべてビジネス日本語です。

> **本資料の位置づけ**  
> 本READMEは、関係者（開発・営業・品質保証・マネジメント）へ製品の価値と機能範囲を共有するための紹介資料です。  
> 現時点は社内ハッカソン向けの **動作するプロトタイプ** です。本番運用（認証・権限管理・実プロジェクトデータの永続化など）は対象外です。

---

## 1. なぜ必要か（解決する課題）

オフショア開発の現場では、BrSEは次の役割を同時に担います。

| 現場で起きやすいこと | 放置した場合のリスク |
| --- | --- |
| タスクの期日と学習計画が衝突する | 遅延の報告が遅れ、信頼を損なう |
| 日報・顧客への質問文の作成に時間がかかる | 本来のブリッジ業務に集中できない |
| 仕様とコードの差異、質問の表現ミスに気づきにくい | 手戻り・品質不良・お客様への印象悪化 |
| 実装で行き詰まったとき、相談のタイミングを逃す | 一人で抱え込み、納期リスクが拡大する |

GROWTH PARTNERは、これらを **「あとで入力する」作業** ではなく、画面上で気づき、下書きまで用意する **伴走型の支援** として設計しています。

---

## 2. 誰のための製品か

| 対象 | 主な利用シーン |
| --- | --- |
| 新人BrSE / SE | 今日やるべきこと、遅れていること、学習目標を一目で確認する |
| 現場のBrSE | 顧客質問の日本語化、仕様とコードの差分確認、日報の下書き |
| PM / 先輩社員 | 遅延の相談メール案、SOS時の状況共有（本人が送信内容を確認したうえで送付） |

デモデータは **生命保険の契約管理システム**（保険料計算、契約更新、解約返戻金など）を想定した架空の案件です。実在するお客様名・実プロジェクトのソースコードは使用していません。

---

## 3. 製品コンセプト

- **カレンダー中心**：予定とタスクを同じリズムで見る。
- **見えないエージェント**：AIはメイン画面を壊さず、必要なときに動く。結果はトーストやチャットで分かる。
- **人が最終判断する**：メール送信・顧客連絡は必ず本人が内容を確認してから行う（下書き作成まで）。
- **オフショア品質の橋渡し**：仕様とコード、質問文、テストケースを日本語ビジネスの文脈で整える。

## 4. 画面の見方（3カラム）

起動すると、次の構成で表示されます。

| 領域 | 役割 |
| --- | --- |
| 左：ナビゲーション | 今日 / カレンダー、プロジェクト一覧、AIツール、表示設定 |
| 中央：作業エリア | 今日のタスク、プロジェクトダッシュボード、週次カレンダー |
| 右：タスク詳細 | 選択したタスクの期日・優先度・メモ・サブタスク |

画面右下のマスコットを押すと、AIチャットが開きます。チャットは右側のタスク詳細とは独立しており、必要なときだけ表示されます。

タブレット・スマートフォンでは、左メニューとタスク詳細はオフキャンバス（スライド表示）になります。

## 5. 主な機能

### 5.1 今日のタスク（デイリーマネジメント）

**できること**

- 本日が期日のタスク、および期限超過タスクを一覧表示します。
- 完了率をプログレスバーで示します。
- 期限超過がある場合、件数と最大遅延日数をバナーで知らせます。
- プロジェクト単位の絞り込み、キーワード検索ができます。
- タスクの追加、完了／未完了の切替ができます。

**使い方の目安**

1. 左メニューの「今日」を開く（起動時の初期画面です）。
2. 行をクリックすると、右側に詳細が開きます。
3. 遅れが見えたら「AIタスク自動調整」または「緊急SOS」を使います。

**提供価値**  
朝一番で「何が遅れているか」を自分で探し回る必要がなくなります。

---

### 5.2 プロジェクトダッシュボード（進捗の見える化）

左のプロジェクト名をクリックすると、そのプロジェクト専用のダッシュボードに切り替わります。

**できること**

- 未着手 / 対応中 / 完了 / 期限超過の件数をカードで表示します。
- 完了率（ドーナツグラフ）、優先度別件数（棒グラフ）を、実際のタスク状態から描画します。タスクを追加・完了・期日変更すると、グラフも追従します。
- プロジェクト内タスクの一覧で、期日・優先度のインライン編集ができます。
- 「タスク追加」から、そのプロジェクトに紐づくタスクを追加できます。

**提供価値**  
WBSの進捗を、会議用の説明資料なしでもその場で説明できます。

---

### 5.3 タスク詳細（引き継ぎ可能な記録）

中央の一覧、ダッシュボード、カレンダー上の予定をクリックすると、右側に詳細パネルが開きます。

**できること**

- タスク名、期日、優先度、メモ、サブタスクを編集できます。
- 変更は自動保存されます（ブラウザのローカル保存）。
- 「完了にする / 未完了に戻す」で状態を切り替えます。

**提供価値**  
口頭の引き継ぎだけでなく、補足と分解した作業を残せるようになります。

---

### 5.4 カレンダー（予定とタスクの一体管理）

左メニューの「カレンダー」から、週表示のカレンダーを開きます。

**できること**

- タスク、AIおすすめ学習、会議、Googleカレンダー由来の予定を色分けして表示します。
- 未完了タスクを画面上部のチップから、時間枠へドラッグ＆ドロップして予定化できます。
- 空いている日付をクリックすると、その日を期日にしたタスク追加画面が開きます。
- 既存の予定をドラッグして、期日を変更できます。
- 「AI分析」で、遅延タスクの再配置案を作成できます。

**凡例**

| 色の意味 | 内容 |
| --- | --- |
| 青 | 通常タスク |
| ミント | AIが提案した学習枠 |
| グレー | 会議・打ち合わせ |
| Google色 | Googleカレンダーから取り込んだ予定 |

---

### 5.5 Googleカレンダー連携

カレンダー画面の歯車から設定し、「Google同期」で取り込みます。

**できること**

- カレンダーIDとAPIキーを保存できます（キーは画面に再表示しません）。
- 本日を中心に前後約1か月の予定を取り込み、カレンダー上のタスクとして表示します。

**ご利用上の前提（重要）**

- 本プロトタイプは **OAuthログインではありません**。Google Calendar API の APIキー方式です。
- 読み取り対象のカレンダーは、Googleカレンダー側で **公開設定** されている必要があります。
- 取り込みは表示用です。Google側の予定をアプリから書き換える機能はありません。

---

### 5.6 AIタスク自動調整（遅延の再スケジュール）

今日ビューの「AIタスク自動調整」、カレンダーの「AI分析」、チャット内の「自動リスケジュール」は、同じ処理です。

**できること**

- 期限超過タスクを分析し、新しい期日案を提示します。
- 承認を得るための **PM宛メール下書き** を作成します。
- 採用した期日はカレンダー上で一時的に強調表示されます。

**人が行うこと**  
提案を確認し、必要なら「PMへ相談メールを送る」からGmailの下書き画面を開きます。アプリが勝手にメールを送信することはありません。

---

### 5.7 緊急SOS（行き詰まりの早期共有）

実装で長時間止まっている状況を想定し、先輩・PMへの相談文面を用意します。

**できること**

- リスクの要約と、連絡文面（編集可能）を表示します。
- 「PM・先輩へ送信（Gmail）」で、確認後にGmail下書きを開きます。

**提供価値**  
「相談してよいタイミングか」で迷っている間に遅延が悪化する、という状態を減らします。  
※デモでは保険システムの計算ロジック実装で停滞している、という想定シナリオを用います。

---

### 5.8 日報の自動生成

左メニュー「日報作成」から利用します。

**できること**

- Gitのコミットログや作業メモを貼り付けると、社内日報の体裁で下書きを生成します。
- 生成後、送信前に本文を自由に編集できます。
- 「上司へ報告書を送信（Gmail）」で、確認後にGmail下書きを開きます。

**日報の構成（生成時）**

- 本日の実施内容
- 進捗（現状と次のアクション）
- 特記事項（なければ「特にございません。」）

**提供価値**  
退勤前の「何を書いたらよいか」を、作業ログから短時間で形にできます。

---

### 5.9 オフショア支援（品質とコミュニケーション）

左メニュー「オフショア支援」から、3つの支援を切り替えます。ファイル未指定の場合は、保険システムのサンプルを用いて動作確認できます。

#### （1）仕様とコード比較

- 仕様書（PDF / テキスト）と、ソースコードのフォルダを指定できます。
- 仕様との不整合、納品後のビジネスリスク、セキュリティ上の懸念（認証情報の直書き、入力検証不足、個人情報の扱いなど）を指摘します。

#### （2）顧客質問レビュー

- 母国語や簡易な日本語で書いた質問を、丁寧なビジネス日本語へ整えます。
- 仕様書に既に書いてある内容を重ねて聞いていないか、お客様への印象リスクを警告します。
- 確認後、お客様宛のGmail下書きを開けます。

#### （3）テスト支援

- **テストケース生成**：要件・受け入れ条件から、リスクベース（正常系／代替系／異常系）のテストケース表を作成します。
- **ユニットテスト生成**：ソースコードから JUnit5（Java）または Jest（JavaScript / TypeScript）のテストコードを生成します。フレームワークは自動判定も可能です。
- 生成結果のコピー、カバーしきれていない観点の注記があります。

**提供価値**  
オフショア成果物を「読んでから指摘する」前に、差分・表現・テストのたたき台を得られます。

---

### 5.10 WBSインポート

左メニュー「WBSインポート」で、CSV / Excel / PDF / テキストを選択できます。

**現時点の挙動（プロトタイプ）**

- ファイルサイズに応じた解析中の表示のあと、対象プロジェクトへサンプルタスク（API設計、ロジック実装、単体テスト）を追加します。
- **実ファイルのWBS構造を完全に読み取る本番パーサーではありません。** 大規模ファイルを扱う際の操作感を示すためのデモです。

正式なWBS取込は、今後の拡張候補です。

---

### 5.11 AIチャット（マスコット）

画面右下のマスコットから開きます。

**できること**

- エージェントの処理経過（読み込み中 → 分析中 など）を時系列で確認できます。
- クイック操作として、自動リスケジュールと緊急SOSを実行できます。
- 自由入力では、遅延タスクがある場合に再スケジュールの相談として処理します。遅延がなければ、その旨を返答します。

本日のタスク件数は、チャット上部のステータス行にも表示されます。

---

### 5.12 表示設定

左下「表示設定」から、作業環境を個人向けに調整できます。設定はブラウザに保存され、次回起動時も維持されます。

- テーマ：ライト / ダーク / グラスモーフィズム
- アクセントカラー（プリセットおよび任意色）
- 背景画像（カード上の文字が読めるよう、薄く表示）

---

### 5.13 初日のあいさつ

その日はじめて開いたとき、本日の期日タスク件数を添えたあいさつ画面を一度だけ表示します。業務開始のスイッチとして使えます。

## 7. ご利用方法

### 動作環境

- Java 17 以上
- Apache Maven
- 生成AI（Google Gemini）のAPIキー（環境変数 `GEMINI_API_KEY` を推奨）
- モダンブラウザ（Chrome 等）

フロントとAPIは **同じプロセス（既定ポート 8080）** で提供します。別途フロント専用サーバーは不要です。

### 起動

```bash
cd backend
mvn spring-boot:run
```

ブラウザで `http://localhost:8080` を開きます。表示が古い場合は、スーパーリロード（Windows では `Ctrl + F5`）を行ってください。

### デモデータについて

プロジェクト・タスクの初期データは、保険システム案件を模した **架空データ** です。追加したプロジェクト／タスク／完了状態は、ご利用のブラウザに保存されます（サーバー上の共有データベースではありません）。

## 8. 技術構成（概要）

| 層 | 内容 |
| --- | --- |
| 画面 | HTML5 / CSS3 / JavaScript（フレームワークなし）。FullCalendar、Chart.js |
| サーバー | Java 17、Spring Boot、Spring AI |
| AI | Gemini（チャット完了。業務ごとに専用プロンプト） |
| ファイル | PDF/テキスト抽出（仕様書・ソースの読み取り） |
| カレンダー連携 | Google Calendar API v3（APIキー。公開カレンダーの読み取り） |

AI機能の例：

- `POST /api/v1/copilot/analyze-schedule` … スケジュール再調整
- `POST /api/v1/copilot/sos-alert` … 緊急SOS
- `POST /api/v1/copilot/generate-nippo` … 日報生成
- `POST /api/v1/copilot/review-offshore` … オフショア支援（比較 / 質問レビュー / テスト）

## 9. 現時点の範囲と今後の扱い

関係者との認識を揃えるため、**今できること** と **まだやらないこと** を明示します。

**今の範囲**

- 一人のBrSEが、デモ案件で一日の流れ（確認 → 調整 → 文書下書き → オフショア支援）を体験できること
- AIの応答はビジネス日本語で、保険ドメインの用語を用いること
- メールはGmailの下書き起動まで（アプリからの直接送信なし）

**対象外（本番化時に別途設計）**

- ログイン・権限・監査ログ
- 複数人でのリアルタイム共有、Jira等との双方向同期
- WBSファイルの正式パース
- Googleカレンダーへの書き込み、およびOAuthによる非公開カレンダーの安全な取得
- 実在顧客の機密データを用いた学習・保管

APIキーを設定ファイルに直書きしたまま、公開リポジトリへプッシュしないでください。提出・保管時は環境変数へ移してください。

## 10. 関係者へのお願い

- **体験の順番（推奨）**  
  今日のタスク → 期限超過の確認 → AI自動調整 → カレンダー → 日報 → オフショア支援
- **評価の観点（推奨）**  
  「入力を減らしているか」「人が最終確認できるか」「お客様向けの日本語として使えるか」
- **機密**  
  デモでは架空の保険システムのみを用いてください。実案件の仕様書・ソースはアップロードしないでください。
